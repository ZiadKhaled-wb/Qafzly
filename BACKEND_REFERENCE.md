## 1. How to use this document

### 1.1 URL construction

The application mounts all API routers under `/v1`. For example:

```text
GET https://api.example.test/v1/paths
```

The application also exposes the following non-versioned operational routes:

| Route | Purpose |
|---|---|
| `GET /health` | Backwards-compatible liveness check |
| `GET /health/live` | Liveness check |
| `GET /health/ready` | Database and Redis readiness check |
| `GET /api-docs` | Swagger UI |
| `/uploads/*` | Static files generated by the pre-S3 upload implementation |

### 1.2 JSON examples

Examples use JSON unless the endpoint explicitly says `multipart/form-data`.
UUIDs, timestamps, URLs, and decimal values are illustrative.

### 1.3 Required versus optional fields

The request tables use:

* **required** — the Zod validator requires the field.
* **optional** — omission is accepted.
* **default** — the validator inserts the shown value before the controller
  runs.
* **nullable** — `null` is accepted in addition to omission.

Unknown keys are normally stripped by Zod's object schemas. The security
critical answer-submission schemas for slides and checkpoints are explicitly
strict and reject unknown keys.

## 2. Transport and conventions

### 2.1 Content types

Use `Content-Type: application/json` for JSON requests. Use
`multipart/form-data` for:

* `POST /v1/users/me/avatar`
* `POST /v1/lessons/:id/pdf`

The global Express app accepts URL-encoded bodies as well, but JSON is the
supported frontend format.

### 2.2 Standard success envelope

Controllers use the following envelope:

```json
{
  "success": true,
  "data": {},
  "message": "تم التنفيذ بنجاح",
  "errors": null,
  "meta": null
}
```

`success` is `true` for HTTP statuses below 400. `data` is `null` when no
payload is returned. `message` may be Arabic, English, or `null`; clients
should use HTTP status and the data shape rather than matching message text for
control flow.

### 2.3 Standard failure envelope

```json
{
  "success": false,
  "data": null,
  "message": "Validation failed",
  "errors": {},
  "meta": null
}
```

Validation failures are HTTP `400` and `errors` is the result of Zod's
`flatten()`. Operational `AppError`s preserve their status and put optional
metadata in `errors`. Unexpected exceptions become HTTP `500`.

### 2.4 Dates, decimals, and JSON

* Prisma `DateTime` values are serialized as ISO-8601 strings.
* Prisma `Decimal` values should be treated as decimal numeric strings when
  precision matters. Do not use binary floating point for payment totals.
* Prisma `Json` fields retain their JSON shape.
* PostgreSQL string arrays are returned as JSON arrays.
* IDs are UUID strings.

### 2.5 Language fields

Many content models have Arabic fields as the canonical required content and
optional English companions. The API does not automatically translate or
select a language-specific projection. The frontend should choose the
appropriate `*Ar`/`*En` or default/English field using the user's language.

## 3. Authentication and authorization

### 3.1 Bearer access token

Authenticated calls must send:

```http
Authorization: Bearer <accessToken>
```

The access token is a JWT signed with the server's access secret. The decoded
payload contains `userId`, `email`, and `role`. Missing or malformed headers
return:

```json
{
  "success": false,
  "data": null,
  "message": "Authentication required",
  "errors": null,
  "meta": null
}
```

An invalid or expired token returns HTTP `401` with
`"Invalid or expired token"`.

### 3.2 Roles

The Prisma `Role` enum contains:

* `STUDENT`
* `PARENT`
* `ADMIN`

`authorize('ADMIN')` returns HTTP `403` and Arabic message
`"غير مصرح لك بالوصول"` when the authenticated role is not allowed.

Parent dashboard routes require both authentication and `PARENT`. A parent
cannot use a student account to access them.

### 3.3 Optional authentication

`optionalAuth` attempts to decode a bearer token when present and otherwise
continues anonymously. It is used by public content and forum reads. The
presence of an optional token can add fields such as the current user's vote,
completion state, or access reason.

### 3.4 Access-control summary

| Surface | Anonymous | Authenticated student | Parent | Admin |
|---|---:|---:|---:|---:|
| Published public paths/modules | Yes | Yes | Yes | Yes |
| Preview lessons | Yes | Yes | Yes | Yes |
| Enrolled non-preview lessons | No | Yes, if enrolled | Parent-specific service rules | Yes |
| Write progress | No | Yes | Yes when service permits | Yes |
| Admin CRUD | No | No | No | Yes |
| Parent dashboard | No | No | Yes | No, unless explicitly implemented |

## 4. Response and error contracts

### 4.1 Pagination metadata

Paginated endpoints return:

```json
{
  "page": 1,
  "limit": 20,
  "total": 143,
  "totalPages": 8
}
```

The metadata is in the top-level `meta` property, not inside `data`.

### 4.2 Empty writes

Delete and action endpoints commonly return `data: null`. Do not require a
resource representation from a successful delete.

### 4.3 Validation errors

Example:

```json
{
  "success": false,
  "data": null,
  "message": "Validation failed",
  "errors": {
    "fieldErrors": {
      "body": ["..."]
    },
    "formErrors": []
  },
  "meta": null
}
```

The exact Arabic field message comes from the validator and may change without
changing the endpoint contract. Display it as a server-provided validation
message when appropriate.

### 4.4 Error handling guidance

* Treat `400` as a request or business-rule correction.
* Treat `401` as a missing/expired session and refresh or sign in.
* Treat `403` as an authorization/access decision; do not retry unchanged.
* Treat `404` as a missing resource or intentionally hidden resource.
* Treat `409` as a duplicate/conflict or concurrent idempotent operation.
* Treat `422` as a valid request that cannot transition the current resource
  state.
* Treat `423` as a temporary account lock.
* Treat `500` as a server failure and show a retry-safe message.

## 5. Pagination, filtering, and serialization

### 5.1 Common pagination defaults

Most list validators default to `page=1` and `limit=20`; maximum limits are
usually 100. Search endpoints cap `limit` at 50. Certificate lists cap it at
50.

Query values are coerced from strings to numbers and, for supported boolean
filters, from strings to booleans.

### 5.2 Sorting

Where present, `order` is `asc` or `desc`. Defaults are documented per
endpoint. Sending unsupported enum values returns `400`.

### 5.3 Soft deletion and publication

Paths and forum content have soft-delete/status concepts. Public list
services normally hide deleted or unpublished records. Admin list endpoints
exist where an administrator needs unpublished content.

## 6. Health and operational endpoints

### `GET /health` and `GET /health/live`

Authentication: none. Rate limiting: bypassed.

Response:

```json
{
  "status": "ok",
  "timestamp": "2026-09-17T15:00:00.000Z"
}
```

These endpoints only prove process liveness; they do not prove that the
database or Redis is available.

### `GET /health/ready`

Authentication: none. Rate limiting: bypassed.

The endpoint runs `SELECT 1` against PostgreSQL and `PING` against Redis.
Success is HTTP `200`; a dependency failure is HTTP `503`.

```json
{
  "status": "ok",
  "checks": {
    "database": "ok",
    "redis": "ok"
  },
  "timestamp": "2026-09-17T15:00:00.000Z"
}
```

### `GET /api-docs`

Swagger UI is unauthenticated and is intended for development/convenience.
It is not part of the stable mobile-client contract.

### `/uploads/*`

Static files are served from the local `uploads` directory. Avatar storage is
currently local/pre-S3. Lesson PDF access is handled through the signed URL
endpoint described below rather than by exposing arbitrary S3 objects.

## 7. Authentication endpoints

### `POST /v1/auth/register`

Authentication: public. Rate limit: auth limiter.

Request body:

| Field | Type | Rules |
|---|---|---|
| `email` | string | valid email, required |
| `password` | string | minimum 8 characters, required |
| `fullName` | string | minimum 2 characters, required |
| `country` | string | exactly 2 characters, optional |
| `language` | enum | `ar` or `en`, default `ar` |
| `learningGoal` | string | optional |
| `skillLevel` | enum | `BEGINNER`, `INTERMEDIATE`, `ADVANCED`; default `BEGINNER` |
| `role` | enum | `STUDENT` or `PARENT`; optional |

Response: HTTP `201`.

```json
{
  "user": {
    "id": "uuid",
    "email": "student@example.com",
    "fullName": "Example Student",
    "language": "ar",
    "skillLevel": "BEGINNER",
    "role": "STUDENT",
    "createdAt": "2026-09-17T15:00:00.000Z"
  },
  "accessToken": "jwt",
  "refreshToken": "opaque-token"
}
```

Side effects:

* Creates the user.
* Creates a `UserStats` row with initial XP/level values.
* Assigns currently active daily quests through the registration flow.
* Does not permit self-registration as `ADMIN`.

Duplicate email: HTTP `409`, `"البريد الإلكتروني مسجل بالفعل"`.

### `POST /v1/auth/login`

Authentication: public. Rate limit: auth limiter.

```json
{
  "email": "student@example.com",
  "password": "secret-password"
}
```

Response: HTTP `200`, with `user`, `accessToken`, and `refreshToken`.
Invalid credentials return HTTP `401` with `"بيانات الدخول غير صحيحة"`.
Repeated failed attempts can temporarily lock the account and return HTTP `423`
with a retry duration in the Arabic message.

### `POST /v1/auth/refresh`

Authentication: public.

```json
{ "refreshToken": "opaque-token" }
```

Response:

```json
{ "accessToken": "jwt" }
```

Refresh tokens are stored server-side in Redis. Invalid tokens return `401`
`"رمز التحديث غير صالح"`; expired tokens return `401`
`"انتهت صلاحية رمز التحديث"`.

### `POST /v1/auth/forgot-password`

Authentication: public. Rate limit: auth limiter.

```json
{ "email": "student@example.com" }
```

Response is intentionally non-enumerating:

```json
{ "success": true }
```

The same successful shape/message is returned whether the email exists.

### `POST /v1/auth/reset-password`

Authentication: public. Rate limit: auth limiter.

```json
{
  "token": "reset-token",
  "newPassword": "new-secret-password"
}
```

Response: `{ "success": true }`. Invalid or expired reset tokens return `401`
with either `"رمز إعادة التعيين غير صالح"` or
`"انتهت صلاحية رمز إعادة التعيين"`.

### `POST /v1/auth/logout`

Authentication: required.

Response: `{ "success": true }`.

Side effect: invalidates the user's refresh token(s) in Redis. Access JWTs
remain cryptographically valid until their normal expiry; clients should
discard them immediately.

## 8. User endpoints

All endpoints in this section require authentication.

### `GET /v1/users/me`

Returns a sanitized current-user profile plus gamification and progress
summary. Sensitive fields such as `passwordHash` are never returned.

Typical data:

```json
{
  "user": {
    "id": "uuid",
    "email": "student@example.com",
    "fullName": "Example Student",
    "displayName": null,
    "bio": null,
    "country": "EG",
    "language": "ar",
    "skillLevel": "BEGINNER",
    "role": "STUDENT",
    "avatarUrl": null,
    "isPublic": true
  },
  "gamification": {
    "level": 1,
    "xp": 0,
    "xpToNextLevel": 100,
    "streak": 0,
    "badges": []
  },
  "progress": {
    "totalPathsEnrolled": 0,
    "totalPathsCompleted": 0,
    "totalLessonsCompleted": 0,
    "currentPath": null
  }
}
```

### `PUT /v1/users/me`

Authentication: required. Validation: profile update schema.

Body fields:

```json
{
  "fullName": "Example Student",
  "displayName": "Example",
  "bio": "Short biography",
  "country": "EG",
  "language": "ar",
  "timezone": "Africa/Cairo",
  "learningGoal": "Build web apps",
  "skillLevel": "INTERMEDIATE",
  "isPublic": true
}
```

All fields are accepted as optional by the current PUT validator, although
clients should send a complete profile when using PUT. Use PATCH for a partial
update.

### `PATCH /v1/users/me`

Same fields as PUT, all optional. `displayName`, `bio`, `country`,
`timezone`, and `learningGoal` accept `null`.

Profile constraints:

* `fullName`: 2–100 characters when present.
* `displayName`: maximum 100 characters.
* `bio`: maximum 500 characters.
* `country`: exactly 2 characters.
* `language`: `ar` or `en`.
* `skillLevel`: `BEGINNER`, `INTERMEDIATE`, or `ADVANCED`.

### `DELETE /v1/users/me`

Soft-deletes/deactivates the account through the user service. Treat the
response as an action result, not as a hard database deletion. Existing
relations are governed by Prisma's relation policies.

### `POST /v1/users/me/avatar`

Content type: `multipart/form-data`. Authentication: required.

The upload middleware expects the avatar file field used by `uploadAvatar`.
On success, data contains:

```json
{ "profilePictureUrl": "/uploads/avatars/<filename>" }
```

No file returns HTTP `400` with `"لم يتم رفع أي ملف"`. URLs are local relative
paths today, not signed S3 URLs.

### `DELETE /v1/users/me/avatar`

Removes the current avatar and returns the updated sanitized user object.

### `PUT /v1/users/me/privacy`

Body:

| Field | Type | Values |
|---|---|---|
| `profileVisibility` | enum | `public`, `private`, `followers` |
| `showProgress` | boolean | optional |
| `showBadges` | boolean | optional |
| `allowMessages` | enum | `everyone`, `followers`, `none` |
| `emailNotifications` | boolean | optional |
| `pushNotifications` | boolean | optional |

The body is stored in the user's `privacySettings` JSON field. Fields omitted
from the request are not necessarily reset; use the returned object as the
source of truth.

### `GET /v1/users/me/privacy`

Returns `{ "privacySettings": {} }` (with the persisted settings shape).

## 10. Paths

### `GET /v1/paths`

Authentication: public. Query:

| Field | Rules |
|---|---|
| `page` | integer ≥ 1, default 1 |
| `limit` | integer 1–100, default 20 |
| `search` | optional string |
| `categoryId` | optional UUID |
| `difficulty` | `BEGINNER`, `INTERMEDIATE`, `ADVANCED`, `ALL_LEVELS` |
| `minPrice` / `maxPrice` | optional non-negative/number filters |
| `isFeatured` | optional boolean |
| `sortBy` | `createdAt`, `price`, or `title`; default `createdAt` |
| `order` | `asc` or `desc`; default `desc` |

Returns paginated public `Path` records. Unpublished and soft-deleted records
are normally excluded.

### `GET /v1/paths/admin/list`

Authentication: `ADMIN`. Same list filters. Intended for unpublished and
administrative content management.

### `GET /v1/paths/:id`

Authentication: optional. Public users receive a published path. An
authenticated admin can receive unpublished content because the route now uses
`optionalAuth`; older helper sheets that describe this as unauthenticated are
stale.

Missing/deleted path: `404` `"المسار غير موجود"`.

### `POST /v1/paths`

Authentication: `ADMIN`.

Body:

```json
{
  "title": "Frontend Foundations",
  "titleEn": "Frontend Foundations",
  "description": "Arabic description",
  "descriptionEn": "English description",
  "categoryId": "uuid",
  "difficulty": "BEGINNER",
  "price": 0,
  "currency": "EGP",
  "featuredImage": "/uploads/path.png",
  "tags": ["web", "frontend"],
  "prerequisites": [],
  "estimatedDuration": 120,
  "isPublished": false,
  "isFeatured": false
}
```

`title` and `description` are required. `price` defaults to 0, `currency` to
`EGP`, and `difficulty` to `BEGINNER`.

### `PUT /v1/paths/:id`

Authentication: `ADMIN`. Partial update. Nullable fields may clear English
titles/descriptions, category, or featured image.

### `DELETE /v1/paths/:id`

Authentication: `ADMIN`. Performs the path deletion behavior implemented by
the service; clients should refresh dependent lists.

### `POST /v1/paths/:id/publish`

Authentication: `ADMIN`.

```json
{ "publish": true }
```

Changes `isPublished`. Publication does not automatically enroll users or
create purchases.

## 11. Modules

### `GET /v1/modules`

Public. Query:

* `pathId` optional UUID. The frontend should provide it to scope the list.
* `isPublished` optional boolean.
* `page`, `limit` defaults 1 and 20; limit maximum 100.

Returns paginated modules. Public content services generally filter
unpublished modules.

### `GET /v1/modules/:id`

Public. Returns one module and its service-selected lesson/boss-battle
relations. Missing module: HTTP `404` `"الوحدة غير موجودة"`.

### `POST /v1/modules`

Authentication: `ADMIN`.

```json
{
  "pathId": "uuid",
  "title": "Module title",
  "titleEn": "Module title",
  "description": "Optional description",
  "order": 0,
  "isPublished": false
}
```

`pathId` and `title` are required; `order` defaults to 0 and `isPublished` to
false.

### `PUT /v1/modules/:id`

Authentication: `ADMIN`. Partial update of title, English title,
description, order, or publication state.

### `DELETE /v1/modules/:id`

Authentication: `ADMIN`. Deleting a module cascades to lessons and dependent
content according to the Prisma schema.

## 12. Lessons

Lessons are the core lesson-player resource. Routes are mounted at
`/v1/lessons`.

### `GET /v1/lessons`

Authentication: optional. Query requires:

```text
moduleId=<uuid>
```

The response is a lesson list projection:

```json
[
  {
    "id": "uuid",
    "title": "Lesson",
    "titleEn": "Lesson",
    "contentType": "TEXT",
    "videoUrl": null,
    "isPreview": true,
    "estimatedTime": 15,
    "order": 0,
    "overviewVideoUrl": null,
    "pdfUrl": null,
    "explanatoryVideoUrl": null,
    "challengeType": "quiz",
    "lockDurationHours": 12,
    "isAccessible": true
  }
]
```

The service limits anonymous/non-enrolled users to preview lessons while
including `isAccessible` for the current user when authentication is present.

### `GET /v1/lessons/:id`

Authentication: optional.

The full lesson response includes lesson fields, `quizQuestions`, a compact
`module` object, `lockStatus`, and an `access` object:

```json
{
  "id": "uuid",
  "title": "Lesson",
  "content": "…",
  "contentType": "TEXT",
  "videoUrl": null,
  "videoDuration": 0,
  "hasQuiz": false,
  "order": 0,
  "isPreview": false,
  "isPublished": true,
  "estimatedTime": 15,
  "overviewVideoUrl": null,
  "pdfUrl": null,
  "explanatoryVideoUrl": null,
  "slidesJson": null,
  "challengeDescription": null,
  "challengeType": "quiz",
  "challengeData": null,
  "lockDurationHours": 12,
  "completionXpAward": 10,
  "rechargeMessageAr": null,
  "rechargeMessageEn": null,
  "rechargeXpBoost": true,
  "rechargeBoostMultiplier": 2,
  "rechargeBoostWindowHours": 24,
  "warmUpJson": null,
  "miniQuestJson": null,
  "quizQuestions": [],
  "module": {
    "id": "uuid",
    "title": "Module",
    "pathId": "uuid"
  },
  "lockStatus": null,
  "access": {
    "reason": "preview"
  }
}
```

`access.reason` is one of `preview`, `enrolled`, `admin`, or `denied`.
Anonymous/non-enrolled users requesting a non-preview lesson receive `403`
`"يجب الاشتراك في هذه الدورة للوصول إلى الدرس"`. An unpublished or missing
lesson is normally hidden as `404` `"الدرس غير موجود"`.

### `GET /v1/lessons/:id/lock-status`

Authentication: required. Returns:

```json
{
  "isLocked": true,
  "remainingSeconds": 3600,
  "message": "…"
}
```

Locking is based on the lesson's lock duration and the user's progress/access
state. The frontend should use `remainingSeconds` rather than parsing the
message.

### `GET /v1/lessons/:id/pdf-url`

Authentication: required. Access is checked for the enrolled student, allowed
parent flows, or admin. Returns a short-lived signed URL:

```json
{
  "url": "https://signed-object-url",
  "expiresIn": 300
}
```

Errors include `404` `"لا يوجد ملف PDF لهذا الدرس"` and `403`
`"غير مصرح لك بالوصول إلى هذا الملف"`.

### `GET /v1/lessons/:id/recharge-status`

Authentication: required. Returns recharge/XP boost state:

```json
{
  "isRecharging": false,
  "remainingSeconds": 0,
  "rechargeMessageAr": null,
  "rechargeMessageEn": null,
  "xpBoostAvailable": true,
  "xpBoostMultiplier": 2,
  "xpBoostWindowHours": 24,
  "xpBoostExpiresInSeconds": 0
}
```

### `POST /v1/lessons`

Authentication: `ADMIN`.

Required: `moduleId` UUID and `title`. Optional fields include `titleEn`,
`content`, `contentEn`, `contentType`, `videoUrl`, `videoDuration`, `hasQuiz`,
`order`, `isPreview`, `isPublished`, `estimatedTime`, `overviewVideoUrl`,
`pdfUrl`, `explanatoryVideoUrl`, `slidesJson`, `challengeDescription`,
`challengeType`, `challengeData`, and `lockDurationHours`.

`contentType` is `TEXT`, `VIDEO`, `QUIZ`, `CODE`, or `MIXED`.
`lockDurationHours` is 0–48 and defaults to 12. Overview and explanatory
video URLs must contain a valid YouTube ID or URL.

### `PUT /v1/lessons/:id`

Authentication: `ADMIN`. Partial update of the lesson fields above. Nullable
content/media fields can be cleared.

### `DELETE /v1/lessons/:id`

Authentication: `ADMIN`. Cascades lesson-dependent records according to the
Prisma schema.

### `POST /v1/lessons/:id/pdf`

Authentication: `ADMIN`. Content type: multipart PDF upload. The middleware
requires a PDF file. Returns `{ "pdfUrl": "s3-or-storage-key" }`.

### `DELETE /v1/lessons/:id/pdf`

Authentication: `ADMIN`. Removes the stored PDF reference/object according to
the storage service and returns `data: null`.

## 13. Enrollment

### `POST /v1/enrollments/paths/:pathId/enroll`

Authentication: required.

Creates an enrollment for the current user. There is no request body.

`404` is returned when the path does not exist or is unpublished:
`"الكورس غير موجود أو غير منشور"`. Duplicate enrollment returns `409`

## 23. Payments

Payments are a manual MVP flow. They are not a card gateway integration.

### `POST /v1/payments/requests`

Authentication: required. Supports optional `Idempotency-Key`.

Body:

```json
{
  "pathId": "uuid",
  "paymentMethod": "vodafone_cash"
}
```

`paymentMethod` is `vodafone_cash`, `instapay`, or `bank_transfer`; it defaults
to the service's default method when omitted.

Response contains:

```json
{
  "requestId": "uuid",
  "referenceCode": "QFLZ-ABCD-1234",
  "amount": "100.00",
  "currency": "EGP",
  "expiresAt": "2026-09-18T15:00:00.000Z",
  "instructions": [
    {
      "method": "vodafone_cash",
      "displayName": "Vodafone Cash",
      "number": "01094811197",
      "instructions": ["…"]
    }
  ]
}
```

Hardcoded manual-payment numbers currently include Vodafone Cash
`01094811197` and InstaPay `01211721488`.

Business conflicts include `404` for a missing/unpublished path,
`409` for an existing enrollment, and state-specific `422` responses.

### Idempotency behavior

The route uses a 24-hour Redis idempotency cache. The cache key is scoped by
authenticated user and header value.

* First successful 2xx response is cached.
* Repeated same-key requests replay the cached response.
* Concurrent same-key requests return `409`:
  `"طلب بنفس Idempotency-Key قيد المعالجة حالياً، يرجى الانتظار قليلاً"`.
* Error responses are not cached.
* Redis failure fails open; the request continues without caching.
* Keys longer than 255 characters return `400`.
* The header is optional for backwards compatibility.

### `GET /v1/payments/requests`

Authentication: required. Query `page`, `limit`, optional `status` and
`search`. Returns only the current user's payment requests.

### `POST /v1/payments/requests/:id/mark-sent`

Authentication: required. Body:

```json
{ "userNotes": "Transfer sent from ..." }
```

The request remains `PENDING`; this records the user's note and does not
activate enrollment.

### `GET /v1/payments/admin/requests`

Authentication: `ADMIN`. Query `page`, `limit`, optional status/search.
Returns all requests with user/path projections.

### `POST /v1/payments/admin/requests/:id/activate`

Authentication: `ADMIN`.

Body:

```json
{
  "subscriptionDurationMonths": 1,
  "adminNotes": "Verified manually"
}
```

Duration is 1–12 months and defaults to 1. Activation creates a `Purchase`
and an `Enrollment` for the requesting user, with an enrollment expiry.

### `POST /v1/payments/admin/requests/:id/reject`

Authentication: `ADMIN`. Body `{ "reason": "Reason" }`, maximum 500
characters. Invalid current state returns `422`.

### `GET /v1/parents/me/children/:childId/settings`

Returns defaults when no settings row exists:

```json
{
  "lockOverrideEnabled": false,
  "customLockDurationHours": null
}
```

### `PUT /v1/parents/me/children/:childId/settings`

Body:

```json
{
  "lockOverrideEnabled": true,
```

`customLockDurationHours` is an integer from 0–24 or `null`.

## 27. Certificates

### `GET /v1/certificates/verify/:code`

Public. Certificate codes are 6–32 characters.

Valid response:

```json
{
  "valid": true,
  "certificate": {
    "certificateCode": "QFLZ-ABCD-1234",
    "recipientName": "Student",
    "pathTitle": "Path",
    "issuedAt": "2026-09-17T15:00:00.000Z",
    "revokedAt": null,
    "revokedReason": null
  }
}
```

Invalid response identifies `NOT_FOUND` or `REVOKED` in the result contract.

### `GET /v1/certificates/me`

Authentication: required. Paginated own certificates. Query `page`/`limit`;
limit maximum 50.

### `GET /v1/certificates/:id`

Authentication: required; owner or admin. Returns one certificate.

### `GET /v1/certificates/:id/download`

Authentication: required; owner or admin. Returns:

```json
{
  "downloadUrl": "https://signed-or-local-url",
  "fileName": "QFLZ-ABCD-1234.pdf"
}
```

### `POST /v1/certificates/admin/issue`

Authentication: `ADMIN`.

```json
{ "userId": "uuid", "pathId": "uuid" }
```

The database has a unique `(userId, pathId)` certificate constraint.

### `POST /v1/certificates/admin/:id/revoke`

Authentication: `ADMIN`.

```json
{ "reason": "Reason with at least 3 characters" }
```

Revocation records timestamp and reason; it does not erase the certificate.

### Automatic issuance

Completing the final lesson through progress can issue a certificate
non-blockingly. The normal student flow should not call admin issue.

## 29. Cross-cutting behavior

### 29.1 Rate limiting

The global rate limiter is installed before `/v1`; authentication register,
login, forgot-password, and reset-password have an additional auth-specific
limiter. Health checks and Swagger are installed before the global limiter.

### 29.2 Transactions and side effects

Several action endpoints write multiple tables. Refresh UI state after success
instead of patching only the immediate response:

* registration: user, stats, quest assignment
* lesson completion: progress, streak, possible certificate
* slide/checkpoint completion: progress, XP audit/stats
* boss submission: battle progress, XP audit/stats
* payment activation: payment request, purchase, enrollment
* parent unlink: parent relation and child settings
* moderation actions: content status and report state

### 29.3 Idempotency

Payment request creation is the only route with explicit idempotency
middleware. Other completion/action routes use unique database keys and
service checks, but clients should still prevent double taps and disable a
submit button while a request is pending.

### 29.4 Server-side reward evaluation

The client must send an answer, not a claimed score/correctness flag, for:

* slide completion
* quest checkpoint completion
* warm-up completion
* boss battle submission

The server evaluates answers and awards XP. Never expose or persist answer-key
logic in client code as an authorization or reward source.

### 29.5 Publication and visibility

A resource can exist in the database while being unavailable publicly because
it is unpublished, deleted, hidden, or inaccessible through enrollment rules.
The frontend should distinguish “not available” from “request failed” using
HTTP status and the `access`/status fields where returned.

### 29.6 Ownership checks

Forum mutations, notification mutations, certificate reads/downloads, parent
child reads, and payment reads are scoped by the authenticated user or role.
Never use a successful UUID validation as proof that the caller may access the
record.

### 29.7 Refresh-token storage

Refresh tokens are server-side Redis state with a seven-day lifecycle in the
auth service. Logout invalidates them. Access-token expiry and refresh-token
expiry are independent client states.

### 29.8 Storage URLs

Avatars currently return local `/uploads/avatars/...` paths. Lesson PDFs use
short-lived signed URLs. Do not cache PDF URLs beyond their `expiresIn`
duration.

## 31. Frontend integration checklist

### Session

* Store access and refresh tokens separately.
* Send the access token as a Bearer token.
* On `401`, refresh once, then retry the original request once.
* On refresh failure, clear the session.
* Clear local tokens on logout.

### Lists

* Read `meta` from the top-level envelope.
* Preserve server defaults when requesting the first page.
* Cap infinite-scroll requests to endpoint-specific maximums.
* Use stable IDs and `order` fields for lesson-player content.

### Lesson player

* Fetch lesson list by `moduleId`.
* Respect `isAccessible` and `access.reason`.
* Do not render non-preview lesson content after a `403`.
* Fetch slides and checkpoints from their dedicated GET routes.
* Treat PDF URLs as expiring and refresh after `expiresIn`.
* Send only answer fields to completion endpoints.
* Disable repeated submission after a successful completion.
* Refresh XP/streak state after reward-bearing actions.

### Payments

* Generate and persist an `Idempotency-Key` per logical payment request.
* Reuse the same key only when retrying the same operation.
* Do not interpret `mark-sent` as activation.
* Poll or refresh payment status after admin review.
* Treat amount as a decimal, not a floating-point display calculation.

### Parent dashboard

* Offer child linking by existing child UUID or email, not child creation.
* Expect billing to be parent-scoped in the current implementation.
* Handle `null` settings values as “use default/no override”.

### Privacy and moderation

* Respect `isPublic`, privacy settings, and service-selected projections.
* Do not assume forum report queues are empty means reporting is broken.
* Use report status values returned by the API.

## 32. Known gaps and source notes

### 32.1 Category routes are not mounted

`category.routes.ts` contains a complete route/controller/service set, but
`routes/index.ts` currently does not import or mount it. Frontend category
requests will fail until the router is wired.

### 32.2 Helper-sheet assumptions that are no longer current

The supplied API reference helper described the following as missing, but the
current repository now wires them:

* `GET /v1/lessons/:lessonId/slides`
* `GET /v1/lessons/:lessonId/checkpoints`
* forum post reporting
* optional authentication on path and forum post reads
* validation on `POST /v1/admin/users/:id/role`

### 32.3 Subscription model versus payment flow

The Prisma schema has no `Subscription` model in the current schema excerpt
used by the payment activation flow; the parent billing response is therefore
not a reliable subscription ledger. Activation currently creates purchase and
enrollment records for the payment requester.

### 32.4 Parent billing scope

`GET /v1/parents/me/billing` is queried by the parent's own user ID. A child
who submits a payment request creates records under the child's account, so
those records do not automatically appear in the parent's billing response.

### 32.5 Admin visibility

Admin access is explicit on admin list/CRUD routes. Optional-auth detail
routes can expose admin context only when the token is supplied. A frontend
admin client should use `/paths/admin/list` for reliable unpublished path
management rather than relying on public detail filtering.
